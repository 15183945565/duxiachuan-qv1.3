# 项目结构与编码规范

## 实际目录

```text
Qv1.3/
  assets/
    Scene/                  LoadingScene、MainScene
    Bundle/                 ui-home 与九个按需功能 Bundle
    Res/                    名为 res 的 Cocos Bundle
      Audio/                正式音频
      Config/               启动配置
      Font/                 字体
      Spine/                角色、战斗、魔界、兽卡等 Spine 包
      Texture/              Loading、Login、Home 与按功能分类的 UI
    Script/
      Managers/             资源和配置管理
      Services/             登录、修复和后端边界
        Backend/            DTO、接口、本地实现、远端实现
      UI/
        Boot/               加载页
        Common/             字体和 UI 分层约定
        Home/               主界面各功能模块
        Login/              手机号登录
  docs/                     交接文档
  settings/                 Cocos 项目设置
  tools/                    只读审计脚本
```

没有实现内容的空目录不会保留。新增系统时，应在出现真实代码或资源后再创建对应目录。

## 命名规则

- TypeScript 类和文件使用 `PascalCase`。
- 变量和方法使用 `camelCase`。
- 常量使用 `UPPER_SNAKE_CASE`。
- 场景节点使用可读的 `PascalCase`，重复节点使用 `_1`、`_2` 后缀。
- 图片资源优先使用英文小写 `snake_case`。
- 已投入使用的中文 Spine 目录不强制改名，以免破坏 atlas 和动态路径。
- 资源与 `.meta` 必须成对移动、提交和删除。

## UI 分层

- `GameSceneLayer`：主场景地图和角色。
- `HudLayer`：常驻主界面控件容器，内部顺序为 `TopHud / LeftDock / RightDock / BottomNav`。
- `PageLayer`：角色、背包、征战、商城、魔界等全屏页面。
- `PopupLayer`：确认框、奖励、邮件、集市和临时遮罩弹窗。
- `GuideLayer / ToastLayer`：新手引导与最高层轻提示。
- Scene 只保留上述常驻壳层；固定功能页和弹窗根节点必须在 `UIHome` Prefab，动态列表保留可编辑模板或明确的 Content 容器。
- 页面关闭时停止 Tween、Spine 回调和 schedule。

## 代码边界

- UI 不直接新增 `fetch`，统一依赖 `IGameBackend`。
- 服务端数字使用整数；货币、掉落和强化结果不能由客户端作为线上真值结算。
- 新业务优先增加独立模块，不继续扩大生命周期编排文件。
- 资源路径统一放在配置模块，禁止在点击回调里散落路径字符串。
- `library/temp/build/profiles` 永远不进入源码交付。
- Creator 运行期间禁止删除 `library/temp/profiles`；清缓存必须先完全退出对应项目的 Creator。

## 提交前

1. 执行 `npm run check:all`。
2. 使用 Creator 打开后确认无 Missing Script 和 Missing Asset。
3. 从 LoadingScene 跑通登录、创建角色、主界面和主要返回流程。
4. 修改场景节点后重新执行层级检查。
5. 新增资源时同时提交 `.meta`。
