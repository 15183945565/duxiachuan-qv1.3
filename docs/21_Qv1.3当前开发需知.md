## 4. 编辑器节点优先

用户很在意“在编辑器里能不能改”。新做 UI 时默认要有清晰节点：

```txt
PageRoot
  Background
  Title
  Header
  List
    Content
      Row_1
      Row_2
  Buttons
```

如果运行时生成了节点，至少保证关键根节点和模板节点能在 Prefab 里看到。用户在编辑器里改了一个模板节点后，运行时不能再用脚本把它改回旧坐标。

## 17. 最近 bug 修复注意事项

- 当前工具上下文可能落在 `Qv1.4`，但本项目只改 `C:\Users\34158\Desktop\game\Qv1.3`。所有搜索、补丁、资源导入和检查都显式用 `Qv1.3` 路径。
- Cocos Feature 组合不允许两个 Feature 同时实现同名具体方法。`getOrCreateDuelLuanshiEditableNode`、`getOrCreateDuelLuanshiEditableSkin` 这类共享 helper 只保留一份实现；其他 Feature 只能写 `abstract` 契约或换唯一方法名。
- 复制 Prefab JSON 节点时必须重新生成 `cc.PrefabInfo.fileId` 和 `cc.CompPrefabInfo.fileId`。重复 `fileId` 会导致编辑器警告“层级面板过滤了重复的 UUID 节点”，并且节点搜索/选择可能异常。
- `npm run check:scene` 现在会检查 duplicate prefab `fileId`；Prefab 批量改完必须跑。
- TypeScript 里不要再用 `LabelOutline` 组件，统一用 `Label.enableOutline`、`outlineColor`、`outlineWidth`。如果编辑器还刷旧 `LabelOutline.color/width` 警告，先确认项目文件里是否还有 `cc.LabelOutline`，没有的话多半是旧编辑器会话或缓存日志。
- 用户说“编辑器改了没同步”时，先查脚本是否覆盖：`setPosition`、`setScale`、`setContentSize`、`removeAllChildren`、`destroy`、`getOrCreate`。

## 18. 邮件页面当前需知

邮件弹窗 Prefab：

```txt
assets/Bundle/UIHome/Prefabs/Popup/MailPanel.prefab
```

邮件主列表，也就是打开邮件后直接看到的三条邮件区域，编辑器路径是：

```txt
MailPanel
  MailBoard
    MailListRoot          // 列表可见窗口，带 cc.Mask + cc.ScrollView
      MailListContent     // ScrollView 的 Content
        MailRowTemplate   // 单条邮件模板
```

要点：

- 用户说“这个页面这部分有滑动区域”时，指的是邮件主列表 `MailListRoot/MailListContent`，不是点击邮件或领取后打开的奖励确认弹窗。
- `MailListRoot` 负责可见范围，带 `cc.Mask` 和 `cc.ScrollView`；调列表显示区域的位置和大小改它的 Position / UITransform Content Size。
- `MailListRoot` 的 `cc.Mask` 类型必须是 `GRAPHICS_RECT`（Prefab 里 `_type: 0`）。如果编辑器中间出现圆形/椭圆遮挡感，优先检查它是不是被保存成 `GRAPHICS_ELLIPSE`（`_type: 1`）。
- `MailListRoot` 的 `cc.ScrollView` 必须 vertical=true、horizontal=false、elastic=false、bounceDuration=0，并把 content 指到 `MailListContent`。
- `MailListContent` 负责承载邮件行。不要让脚本滚动 `MailListRoot`，否则编辑器里调好的窗口会被带着跑。
- `MailRowTemplate` 必须放在 `MailListContent` 下。运行时复制它生成邮件行，并只刷新标题、时间、预览文字、未读红点和领取按钮状态。
- 编辑器模板里的 `MailRowTitle`、`MailRowTime`、`MailRowPreview`、`MailRowClaimButton`、`MailUnreadDot` 的位置、尺寸、字号和对齐应以编辑器为准；`mailUsesEditorLayout` 为 true 时运行时不能重设这些布局属性。
- 如果模板文字在编辑器里显示 `????`，先把 Prefab 里的示例文字改成真实 UTF-8 中文或用 `\uXXXX` 转义写入。运行时代码只换 `Label.string`，并保留 `UITransform.contentSize`，避免启动后和编辑器不一致。
- 改完邮件层级后跑 `npm run check:type`、`npm run check:scene`、`npm run check:ui`。`check:ui` 会检查 `MailListRoot/MailListContent/MailRowTemplate` 这条路径，以及 `MailListRoot` 的 `cc.Mask + cc.ScrollView` 组件配置。
- 邮件状态规则：`state=0` 未读，列表行显示红点；点击邮件信息框进入详情弹窗后变 `state=1`，列表行只隐藏红点，保持正常颜色；点击邮件信息框里的“领取”按钮或详情弹窗里的“确认领取”后变 `state=2`，列表行红点隐藏，行内原 UI 和文字保持原色，最上层加 `MailRowClaimedDimOverlay` 统一透明黑遮罩来整体调淡，不能逐个改 Sprite/Label 颜色，也不能用 Sprite 灰阶黑白化，按钮文字显示“已领取”。
- 邮件红点和已领取调淡绝对互斥。隐藏 `MailUnreadDot` 时不要再调用通用 `applyUiSkin(...)`，因为 `applySpriteFrameToNode(...)` 会在异步贴图加载完成后把节点 `active=true`，导致红点被重新打开；隐藏时应同步作废该节点的 `skinApplyVersions`。

邮件领取奖励确认弹窗，也就是截图里标题为“战场产出材料”的弹窗，编辑器路径是：

    BattleHostMailDetailDim
    BattleHostMailDetailBoard
      BattleHostMailDetailBoardSkin
      BattleHostMailDetailTitleSkin
      BattleHostMailDetailTitle
