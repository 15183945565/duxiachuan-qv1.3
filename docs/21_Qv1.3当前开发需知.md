## 4. 编辑器节点优先

用户很在意“在编辑器里能不能改”。新做 UI 时默认要有清晰节点：

```txt
PageRoot
  Background
  Title
  Header
  List
    Content
      Row_1
      Row_2
  Buttons
```

如果运行时生成了节点，至少保证关键根节点和模板节点能在 Prefab 里看到。用户在编辑器里改了一个模板节点后，运行时不能再用脚本把它改回旧坐标。

## 6. 江湖逃杀当前状态

页面节点：

```txt
Canvas/MainRoot/PageLayer/DuelPanel/DuelJianghuTaoshaPage
```

重要节点：

```txt
DuelJianghuTaoshaPage
  JianghuTopInfoRoot
  JianghuTaoshaRooms
  JianghuActorLayer
  JianghuInvestRoot
  JianghuSideButtons
  JianghuRecordPage
  JianghuRankPage
  JianghuResultPopup
```

当前规则：

- 倒计时默认 `20` 秒。
- 投入数量只允许 `1`、`10`、`100`。
- 投入数量通过上拉/下拉固定选项选择，不做手输。
- 没有投入时，点击房间只选中房间，玩家不走进房间。
- 玩家已经投入后切换房间，不重新播放首次进入流程，直接刷新到新房间逻辑。
- 最后 `3` 秒不能切换投入房间。
- 房间门口速度不能变慢，门口停顿时间在 `HomeDuelConfig.ts` 的 `DUEL_JIANGHU_ROOM_DOOR_PAUSE_TIME`，当前为 `0`。
- “杀手出现”横幅只在江湖逃杀主页面显示，记录页和排行页不能显示。
- 结算弹窗 `JianghuResultPopup` 会在 3 秒后自动关闭，也可以点空白遮罩关闭。

## 7. 江湖逃杀反杀/失败逻辑

当前前端演示逻辑按这些情况展示，后端接入时要保留字段表达能力：

- 刺客、江湖双煞等普通杀手命中玩家投入房间：躲避失败。
- 杀手没有命中玩家投入房间：躲避成功。
- 叛门逆徒进入百战将军房间：被反杀。
- 叛门逆徒进入其他四个房间：躲避失败。
- 记录页要能展示反杀、双杀等情况；如果双杀，需要能显示两个房间名。

## 8. 江湖逃杀音效

资源在：

```txt
assets/Res/Audio/Duel/duel_jianghu_taosha_bgm.mp3
assets/Res/Audio/Duel/duel_jianghu_countdown_3s.mp3
assets/Res/Audio/Duel/duel_jianghu_success.mp3

```

当前逻辑：

- 进入江湖逃杀页面后循环播放背景音乐。
- 进入记录页或排行页时背景音乐继续播放。
- 倒计时到 3 秒时播放 3 秒倒计时音效。
- 成功或失败音效只在玩家本期实际投入后播放。
- 音效播放时背景音乐临时压低，音效结束恢复。

JianghuRankPage

  JianghuRankTopRoot

规则：

- 去掉旧的 `躲避榜`、`连胜榜`、`今日榜`、`上周榜`按钮逻辑；旧节点会隐藏。
- 顶部标题显示 `周榜`。
- 前三名既显示在顶部大旗区域，也显示在下面列表的第 1、2、3 行。
- 顶部前三名不显示投入元宝数，下面列表会显示。
- 列表列顺序是：名次、头像、玩家名、投入元宝数、奖励（元宝数量）。

- `JianghuRankInvestRow_1` 是当前最重要的样式参考行；用户编辑它后，其他排行行要同步同类子节点样式。
- 排行列表可能滚动，滚动区同样不要弹性回弹。

## 11. 字体当前状态

当前 `UIFont.ts` 内部把 `applySimKaiFont`、`applySimKaiFontToTree`、`applySimKaiFontToRichText` 都转到了 `Microsoft YaHei`。

后续不要在页面里到处硬写字体名。要换全局字体，优先改 `UIFont.ts`；要调页面视觉，只改字号、颜色、行高、描边和对齐。

## 12. 全局点击音效

全局按钮点击音效资源：

```txt
assets/Res/Audio/UI/button_click.mp3
```

安装入口：

```txt
assets/Script/UI/Boot/BootLoadingView.ts
assets/Script/UI/Home/MainHomeView.ts
```

实现：

```txt
assets/Script/UI/Common/GlobalButtonClickAudio.ts
```

如果某个按钮没有声音：

1. 先检查节点是否挂了 `cc.Button`。
2. 如果只是可点击图片，检查节点名是否符合 `Btn*`、`*Button`、`Tab*`、`*Back`、`*Close`、`*Confirm` 等匹配规则。
3. 不要给单个按钮单独写播放逻辑，优先让它接入全局规则。

## 14. 角色 Spine 当前规则

- 角色与武器等级绑定，换到相应武器等级时显示对应人物。
- 男角色攻击只用 `skill0`。
- 女角色攻击只用 `skill2`。
- 角色页、主界面、战斗页等有人物显示的地方要同步同一套角色 Spine 资源和缩放规则，不要只改一个页面。

## 15. 常用检查

小改动：

```bash
npm run check:type
npm run check:code
```

涉及 UI、Prefab、资源：

```bash
npm run check:ui
npm run check:scene
npm run check:resources
```

较大改动：

```bash
npm run check:all
```

文档修改一般不需要跑完整检查，但如果文档同步了节点规则，建议至少用 `rg` 检查节点名是否真实存在。
