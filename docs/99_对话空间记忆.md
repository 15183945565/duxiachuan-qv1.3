## 编码与编辑注意

- 不要用 `git reset --hard` 或 `git checkout --` 破坏用户手改。
- Cocos 场景文件是 JSON，批量改要特别小心 UUID、节点层级、组件数组和 `__id__` 引用。
- 如果用户说“编辑器里没变”，优先检查是不是代码运行时覆盖了编辑器里的节点属性。
- `????` 占位解决办法：遇到 Cocos Prefab/Scene 模板文字在编辑器里显示 `????`，不要只在运行时代码里替换中文。先把 Prefab/Scene 的示例文字改成真实 UTF-8 中文，或用 `\uXXXX` 转义写入；运行时只更新 `Label.string`，并在更新前后保留/恢复编辑器里的 `UITransform.contentSize`，避免覆盖 Position、Scale、字体和对齐，这样启动后才会和编辑器一致。
- 如果启动后和编辑器不一致，优先检查：
  - 脚本里是否 `setPosition`、`setScale`、`setContentSize`
  - 是否 `ensureNode` 运行时重建了节点
  - 是否预制/场景引用了旧 SpriteFrame
  - Cocos 是否还没保存场景或资源没重新导入
- 如果出现紫色块，通常是 spriteFrame 为空、资源路径不对、meta/uuid 断了。

## 2026-08-08 邮件列表与编辑器同步记忆

- 邮件主列表和邮件领取奖励确认弹窗要分开记：打开邮件后直接看到的列表区域是 `MailPanel/MailBoard/MailListRoot/MailListContent/MailRowTemplate`；点击邮件/领取后出现的“战场产出材料”确认弹窗是 `MailPanel/BattleHostMailDetailTemplate`。`BattleHostMailDetailTemplate` 现在是 `MailPanel.prefab` 里的隐藏编辑器模板，默认 inactive，运行时只填充标题、奖励和按钮事件，不要再把它当作主列表滑动区域来改。
- 邮件状态显示规则：`state=0` 显示未读红点；点击邮件信息框进入详情弹窗后为 `state=1`，只隐藏红点，不调淡；点击邮件信息框里的“领取”按钮或详情弹窗里的“确认领取”后为 `state=2`，列表行隐藏红点，原 UI 和文字保持原色，最上层加 `MailRowClaimedDimOverlay` 统一透明黑遮罩来整体调淡，不能逐个改 Sprite/Label 颜色，也不能用 Sprite 灰阶黑白化，按钮显示“已领取”。
