## 2. 编辑器里改了，启动后没同步

常见原因：

1. 代码运行时重新 `setPosition`、`setScale`、`setContentSize`。
2. 代码运行时 `clearChildren`、`removeAllChildren`、`destroy` 后重新创建节点。
3. 该 UI 本来就是运行时创建，prefab 里没有稳定节点。
4. 节点改名后，代码仍按旧名字 `findNode`。

排查：

```powershell
rg -n "节点名|setPosition|setScale|setContentSize|clearChildren|removeAllChildren|destroy|getOrCreate" assets\Script\UI\Home
```

正确修法：

1. 在 prefab 里补稳定节点。
2. 代码优先 `getChildByName/findNode` 读取 prefab 节点。
3. 找不到节点时才运行时创建 fallback。
4. 已存在编辑器节点时，只刷新图片、文字、点击事件，不重置位置、大小、缩放。

推荐模式：

```ts
let node = parent.getChildByName('SomeNode');
if (!node?.isValid) {
    node = this.createNode('SomeNode', parent, width, height, x, y);
}
node.active = true;
```

贴图刷新用：

```ts
this.applyUiSkinKeepingEditorSize(node, skinPath, fallbackWidth, fallbackHeight);
```

不要对已存在编辑器节点强行写死：

```ts
node.setPosition(...)
transform.setContentSize(...)
parent.removeAllChildren()
```

## 3. 运行时生成 UI 要改成编辑器可拖

步骤：

1. 在对应 prefab 下新增根节点，比如 `FeatureRoot`。
2. 下面放可拖的子节点，比如 `Slot_1`、`Icon_1`、`Amount_1`、`Button`。
3. 代码绑定时先找这些节点。
4. 代码只刷新动态内容，不清空根节点。
5. 缺节点时才补 fallback，避免旧 prefab 直接崩。

## 4. 手动改 prefab JSON 的注意事项

优先在 Cocos Creator 编辑器里新增节点。如果必须手动改 prefab JSON，必须注意：

1. `cc.Node`、`cc.UITransform`、`cc.Sprite`、`cc.Label`、`sp.Skeleton` 都要有正确引用。
2. 父节点 `_children` 必须加入新节点 `__id__`。
3. 每个 `cc.PrefabInfo.fileId` 和 `cc.CompPrefabInfo.fileId` 必须唯一。
4. 不要复制旧节点后保留重复 `fileId`。
5. 不要手写不存在的 spriteFrame UUID。

改完必跑：

```powershell
npm run check:ui
npm run check:scene
npm run check:resources
```

## 5. 动态资源不能直接乱写 UUID

有些资源可以在代码里通过路径加载，但 prefab 里不一定能直接写 `uuid@f9941`。

如果资源 `.meta` 里没有 sprite-frame 子资源，或者资源属于动态加载路径，prefab 节点可以先保留空 Sprite，运行时用代码加载。

正确方式：

```ts
this.applyUiSkinKeepingEditorSize(iconNode, material.iconPath, 78, 78);
```

不要为了让编辑器里显示图标，直接编一个或猜一个 `@f9941`。这会导致资源校验失败或运行时加载异常。

## 6. 问号文字

表现：

- 编辑器或运行时看到 `????`。
- 中文示例文字不显示。

原因：

1. prefab 文本保存时编码错。
2. 代码里写了错误编码字符串。
3. Label 字体/字号/宽度太小导致显示异常。

解决：

1. prefab 示例文字用真实 UTF-8 中文。
2. 代码里的中文可以直接写 UTF-8，或用 `\uXXXX`。
3. 运行时只改 `Label.string`，不要顺手改 `UITransform`、Position、Scale。
4. 如果是编辑器控制的布局，字号、行高、对齐以 prefab 为准。

## 7. 邮件列表遮罩和滚动留白

邮件列表路径：

```txt
MailPanel
  MailBoard
    MailListRoot
      MailListContent
        MailRowTemplate
```

正确配置：

- `MailListRoot` 带 `cc.Mask + cc.ScrollView`。
- Mask 必须是矩形 `GRAPHICS_RECT`，prefab 里 `_type: 0`。
- `ScrollView.elastic=false`，`bounceDuration=0`。
- `MailListContent` 才是移动内容，`MailListRoot` 是窗口，不要让脚本移动窗口。
- 第一条邮件在顶部，最后一条到底部，不允许拉出大留白。

红点和已领取状态：

- 未读显示红点。
- 已读只隐藏红点，不调淡。
- 已领取用最上层黑色半透明遮罩整体调淡。
- 红点和已领取遮罩互斥。

## 8. 通用弹窗串样式

很多功能共用 `ConfirmPopup`。如果一个功能打开后改了弹窗结构，关闭时必须恢复默认状态，否则下一个功能会串样式。

常见问题：

- 商铺购买用了背包属性弹窗尺寸。
- 魔界房间确认残留到普通确认弹窗。
- 标题底框、叉号、按钮位置被其他功能覆盖。

解决：

1. 普通确认、数量购买、魔界房间确认、魔界层数确认分别有自己的初始化/隐藏逻辑。
2. 打开某个变体前先隐藏其他变体节点。
3. 只换底图时不改尺寸。
4. 用户在编辑器调过的位置，代码要优先保留。

## 9. 资源加载失败

表现：

- 页面显示“资源加载失败”。
- Spine 不播放。
- Sprite 空白。

排查顺序：

1. 资源是否存在 `.meta`。
2. 动态路径是否写进配置。
3. 资源前缀是否在 `HomeAssetBundleManifest.ts` 对应 bundle。
4. prefab 是否在 `HomeUIPrefabManifest.ts`。
5. 是否误删了动态资源，因为 `rg` 搜不到字符串不代表资源不用。

检查：

```powershell
npm run check:resources
npm run check:bundles
```

## 12. 超值礼包材料包：运行时生成 UI 要落回编辑器节点

问题表现：

- 编辑器里看不到礼包材料、数量、购买按钮或放置光效，导致用户无法拖动位置。
- 运行时能显示，但编辑器里只有背景图；或者编辑器改了位置，启动后又被代码重置。

正确节点：

```txt
assets/Bundle/UIHome/Prefabs/Page/ValueGiftPanel.prefab

ValueGiftPanel
  ValueGiftMaterialPackRoot
    ValueGiftMaterialSlot_1
      ValueGiftMaterialEffect_1
      ValueGiftMaterialIcon_1
      ValueGiftMaterialAmount_1
    ValueGiftMaterialSlot_2
      ValueGiftMaterialEffect_2
      ValueGiftMaterialIcon_2
      ValueGiftMaterialAmount_2
    ValueGiftMaterialBuyButton
      ValueGiftMaterialBuyYuanbaoIcon
      ValueGiftMaterialBuyPrice
```

代码位置：

```txt
assets/Script/UI/Home/HomeFeatureGiftShare.ts
assets/Script/UI/Home/HomeGiftConfig.ts
```

修法原则：

- `HomeFeatureGiftShare.ts` 只能优先复用上面的编辑器节点，不能 `removeAllChildren()` 后整套重建。
- `buildValueGiftMaterialPack(...)` 只刷新图标、数量、价格、按钮点击事件和 Spine/SpriteFrame 资源。
- `ValueGiftMaterialIcon_1/2` 的 prefab 示例图标可以为空，运行时通过 `HomeGiftConfig.VALUE_GIFT_MATERIAL_PACK_ITEMS` 绑定真实材料图标；不要手猜 spriteFrame UUID。
- `ValueGiftMaterialEffect_1/2` 是材料放置光效，用户要改大小或位置时就在编辑器拖这两个节点。
- `ValueGiftMaterialBuyButton` 是购买按钮，用户要改按钮位置、价格数字和元宝图标位置时都在这个节点下面改。

验证：

```powershell
npm run check:type
npm run check:resources
npm run check:ui
```

如果将来又出现“编辑器改了启动不生效”，先搜：

```powershell
rg "ValueGiftMaterial|buildValueGiftMaterialPack|clearValueGift" assets/Script assets/Bundle/UIHome
```

重点确认是否又出现了清空根节点、重设坐标、重设尺寸的代码。

## 13. 编辑器布局已经改好，但启动后还是旧布局

问题表现：

- 用户在 Cocos Creator 里拖好了位置，启动游戏后又变回旧位置。
- 编辑器里一行显示正常，运行时其他行/弹窗/列表没有同步。
- 弹窗内容突然空白，或者魔界层数弹窗里的房间信息、需求材料、今日次数不显示。

实际排查：

```powershell
rg "setPosition|setContentSize|removeAllChildren|destroyAllChildren|active = false|MagicFloorInfoRoot|MagicFloorMaterialRoot" assets/Script/UI/Home
```

重点看运行时代码有没有：

- 每次打开弹窗都强制 `setPosition(...)` 覆盖编辑器坐标。
- `removeAllChildren()` 清空了用户在 prefab 里调好的节点。
- 把某个业务弹窗节点误认为旧节点隐藏，例如把 `MagicFloorInfoRoot` 当成普通提示节点隐藏。
- 只按第一个节点写死了坐标，复制出的其他行没有调用同步函数。

实际修法：

- 保留编辑器节点，运行时只刷新 `Label.string`、`SpriteFrame`、数量、颜色、按钮事件。
- 对确实需要代码创建的列表项，先读取编辑器模板节点的布局，再复制到其他项。
- 兜底坐标只放在 `Home*Config.ts`，且只在节点缺失时使用；不要让兜底值覆盖已存在节点。
- 修改后同时打开 prefab 和游戏预览验证，不能只看其中一个。

本次典型案例：

```txt
assets/Script/UI/Home/HomeViewAdventure.ts
assets/Script/UI/Home/HomeMagicConfig.ts
assets/Bundle/UIHome/Prefabs/Popup/ConfirmPopup.prefab
```

魔界层数进入弹窗使用 `ConfirmPopup.prefab` 的专用子节点：

```txt
ConfirmPopupBoard
  MagicFloorInfoRoot
  MagicFloorMaterialRoot
  MagicFloorDailyRoot
  MagicFloorRequirementTicket
  MagicFloorRequirementMaterial_1..5
```

`layoutMagicFloorConfirmPopup(...)` 不能隐藏这些专用节点；`hideMagicMonsterRoomPromptNodes(...)` 已改成可传参，魔界层数进入弹窗调用时不要隐藏 `MagicFloorInfoRoot/MagicFloorMaterialRoot/MagicFloorDailyRoot`。

## 14. 通用弹窗串样式或不同业务互相污染

问题表现：

- 用户说“除了背包物品属性弹窗，其它都用通用弹窗”，但某个商城/集市/魔界弹窗变成了背包属性框大小。
- 某个业务临时换了弹窗底框后，其它确认弹窗跟着错。
- 通用确认弹窗里的标题底框、按钮位置在征战生效，魔界或集市没同步。

实际排查：

```powershell
rg "ConfirmPopup|GiftTransferConfirmPopup|ItemDetailPopup|showConfirm|showQuantityConfirm|layoutMagicFloorConfirmPopup" assets/Script/UI/Home assets/Bundle/UIHome/Prefabs
```

处理原则：

- `ItemDetailPopup.prefab`、`BagIllustrationDetailPopup.prefab` 是背包/图鉴物品属性专用，不要拿它们同步通用确认弹窗。
- `ConfirmPopup.prefab` 是大多数“取消/确定”确认弹窗的唯一模板。用户在编辑器里改 `ConfirmPopupBoard`、`ConfirmPopupTitleSkin`、`ConfirmCancelButton`、`ConfirmAcceptButton` 后，代码必须同步到所有调用 `ConfirmPopup` 的场景。
- 元宝赠送二次确认用 `GiftTransferConfirmPopup.prefab`，但视觉规则应跟通用弹窗保持一致，不能误套背包属性弹窗尺寸。
- 若业务需要特殊信息区，例如魔界层数进入弹窗，应该在 `ConfirmPopup.prefab` 里加业务专用 Root，并通过开关显示，不要另建一套完全不可编辑的运行时 UI。

验证方法：

```powershell
npm run check:type
npm run check:resources
npm run check:scene
```

再手动点以下场景：征战挑战确认、魔界层数进入、商铺购买、集市购买/出售、异兽激活、元宝赠送确认。

## 15. 输入框/EditBox 变形、看不到、或 prefab 报 corrupted component

问题表现：

- Cocos 控制台出现 `Corrupted component value`、`PLACEHOLDER_LABEL`、`EditBoxTouch`、`_destroyImmediate is not a function`。
- 输入框文字和占位文字大小不一致，输入位置偏。
- 代码创建的输入框层级不对，看不到底框或只能看到文字。

实际排查：

```powershell
rg "EditBox|PLACEHOLDER_LABEL|EditBoxTouch|ProfileRealName|GiftTransferUid" assets/Script/UI/Home assets/Bundle/UIHome/Prefabs
```

修法原则：

- 不要随便在已有 prefab 上手动拼 `EditBox` 内部组件结构；Cocos `EditBox` 依赖内部节点，错误复制很容易让 prefab 组件损坏。
- 正式 UI 要在 prefab 里预留可拖节点，例如实名弹窗在 `ProfilePopup.prefab/ProfileRealNamePopup/ProfileRealNameBoard`，赠送 UID 输入在 `GiftPanel.prefab/GiftTransferRoot`。
- 代码只读取现有节点并绑定 `EditBox.string`、placeholder、输入回调；如果必须创建，创建后不要复用坏掉的 placeholder label UUID。
- 如果编辑器打开就报错，先删除坏的动态输入节点，回退到普通 `Node + Sprite + Label` 可见结构，再重新在 Cocos 编辑器里加标准 `EditBox`。

## 16. 战斗/魔界攻击节奏看起来过快或伤害时机不对

问题表现：

- 用户要求“每秒一次硬性规则”，但画面像一秒打了多次。
- 加了第二个攻击特效/音效后，动画节奏看起来更快。
- 受击特效出现时血量没扣，攻击结束才扣血。

实际排查：

```powershell
rg "MAGIC_BATTLE_ATTACK_INTERVAL|MAGIC_BATTLE_ATTACK_START_DELAY|MAGIC_BATTLE_ROLE_ATTACK_TIME_SCALE|playMagic|applyMagic|HitEffect|attackEffect" assets/Script/UI/Home
```

修法原则：

- 伤害结算独立于视觉特效。每秒只结算一次伤害，结算点放在第一段命中帧。
- 第一段命中时播放攻击特效和音效，同时扣血；第二段动作可以保留动画表现，但不要再次扣血。
- 不要因为补第二段特效而重启或提前下一轮攻击计时；计时器只认统一攻击间隔。
- 怪物受击动作结束后必须回到 idle/stand 循环，不能停在受击最后一帧。

相关文件：

```txt
assets/Script/UI/Home/HomeFeatureMagicBattle.ts
assets/Script/UI/Home/HomeMagicConfig.ts
assets/Bundle/UIHome/Prefabs/Page/MagicMonsterBattlePanel.prefab
```

## 17. 资源删除或换皮后页面黑屏/资源加载失败

问题表现：

- 页面只剩黑屏。
- 征战提示“战斗资源加载失败”。
- 人物攻击特效、音效突然没了。

实际排查：

```powershell
npm run check:resources
rg "missing|not found|load failed|加载失败" assets/Script tools docs
```

再查最近删改：

```powershell
git status --short
git diff --name-status
```

修法原则：

- 不要把“没有直接在 prefab 里引用”的资源当废资源删掉。很多 Spine、音效、攻击特效是运行时通过配置路径加载。
- 删除前必须用 `rg` 查脚本配置、manifest、动态路径拼接；动态资源宁可先保留。
- 若误删，优先从 Git 或用户 UI 归档恢复原资源路径和 `.meta`，保证 UUID 不断。
- 换 UI 时如果用户只要求换图，不要顺手改 `Content Size`，否则会造成规格错乱。

## 18. 文档更新习惯

每次解决完可复用问题，应同步更新：

```txt
docs/99_对话空间记忆.md
docs/25_Qv1.3常见问题解决办法.md
```

写法要求：

- 先写现象，再写排查命令，再写实际修法和关键文件。

- 明确区分正式逻辑、临时预览逻辑、测试投放数据。
- 任何文档都要标明默认工程是 `Qv1.3`，避免后续误改 `Qv1.4`。
