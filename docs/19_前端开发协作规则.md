## Cocos 文件规则

最容易冲突的文件：

```text
.scene
.prefab
.meta
资源目录
```

规则：

```text
1. 同一时间尽量只有一个人改同一个页面。
2. 改某个页面前，告诉后端同学不要动对应 prefab。
3. 保存 Cocos 场景后，要检查 Git diff 是否出现无关大面积变化。
4. 不要随便删除 .meta 文件。
5. 不要把资源直接拖来拖去后不检查引用。
```

## 前端目录整理方向

后续建议逐步整理成：

```text
assets/Script/Net/
  ApiClient.ts
  ApiRoutes.ts
  ApiTypes.ts
  WsClient.ts

assets/Script/Data/
  PlayerData.ts
  BagData.ts
  ShareData.ts
  DaoYouData.ts

assets/Script/Mock/
  MockPlayer.ts
  MockBag.ts
  MockShare.ts
  MockDaoYou.ts

assets/Script/Config/
  GameEnv.ts
  ServerConfig.ts
```

UI 页面脚本只负责显示和交互，不要把接口地址和复杂数据转换写散在 UI 里。

## 接口调用规则

禁止在 UI 脚本里写死服务器 IP：

```ts
fetch("http://103.144.241.103:8795/api/player/profile")
```

推荐：

```ts
ApiClient.get(ApiRoutes.PLAYER_PROFILE)
```

接口路径尽量使用相对路径：

```text
/api/player/profile
/api/bag/items
/api/share/tasks
/api/daoyou/list
/ws
```

这样后续本地、测试服、正式服都能切换。

## Mock 数据规则

后端没完成前可以用 Mock，但 Mock 必须集中管理。

规则：

```text
1. Mock 字段尽量和接口文档一致。
2. 不要把 Mock 数据散落在每个 UI 脚本里。
3. 接真实后端时，优先改 ApiClient 或 Data 层。
4. UI 层只接收整理好的数据。
```

## 前端提交前检查

普通代码和 UI 调整后建议执行：

```bash
npm run check:type
npm run check:code
npm run check:ui
```

涉及资源、Prefab、动态路径时再执行：

```bash
npm run check:resources
```

如果只是文档修改，可以不跑完整检查。

## 发给后端前必须说明

每次 push 后告诉后端同学：

```text
是否已经 push
commit 号
主要改了哪些页面
是否新增资源
是否新增接口字段
哪些地方还在 Mock
需要她重点检查什么
```

示例：

```text
我已经推送前端，commit 是 xxxx。
这次主要改了道友页和分享页。
接口还没接真实后端，仍然用 Mock。
你拉最新 main 后可以看 UI。
```

## 拉取后端修改后要检查

从 GitHub 拉到后端同学改回来的前端后：

```bash
git pull --ff-only origin main
git log --oneline -5
git status -sb
```

如果她改了 `.scene`、`.prefab`、`.meta`，打开 Cocos 后重点检查：

```text
节点是否丢失
资源是否丢失
图片是否变成默认图
按钮事件是否还在
脚本组件是否还挂着
运行时是否报错
```

## 前端当前重点

当前前端还在快速搭 UI 和整理结构阶段。优先保证：
