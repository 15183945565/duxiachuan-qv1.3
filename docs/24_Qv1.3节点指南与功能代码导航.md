# Qv1.3 节点指南与功能代码导航

## 1. 先记住的规则

1. 所有 Cocos 可编辑 UI prefab 主要在：
   - `assets/Bundle/UIHome/Prefabs/Page`
   - `assets/Bundle/UIHome/Prefabs/Popup`

2. 所有首页功能代码主要在：
   - `assets/Script/UI/Home`

3. 后端接口边界主要在：
   - `assets/Script/Services/Backend/IGameBackend.ts`
   - `assets/Script/Services/Backend/GameBackendTypes.ts`
   - `assets/Script/Services/Backend/RemoteGameBackend.ts`
   - `assets/Script/Services/Backend/LocalPreviewBackend.ts`
   - `assets/Script/Services/BackendRuntime.ts`
   - `assets/Script/Services/RuntimeConfig.ts`

4. 如果编辑器里改了节点位置，启动后没有同步，通常是这三种原因：
   - 代码运行时又重新设置了该节点的 `position/size/scale`。
   - 该节点不是 prefab 里的节点，而是代码运行时创建的节点。
   - prefab 节点名被代码按名字查找，改名后代码没有同步。

5. 如果要让后端同学接数据，不要让后端直接改 UI 节点。后端应该对接 `IGameBackend` 或新增同级接口，再由功能模块读取接口结果刷新 UI。

6. 新增资源必须保留对应 `.meta`，新增 prefab 必须加入 `HomeUIPrefabManifest.ts`，新增功能资源如果不在 `res` 公共包里，还要检查 `HomeAssetBundleManifest.ts`。

## 2. 项目启动与 UI 加载流程

### 2.1 启动入口

| 作用 | 文件 |
| --- | --- |
| 后端模式初始化，本地预览或远端接口 | `assets/Script/Services/BackendRuntime.ts` |
| 运行时配置读取 | `assets/Script/Services/RuntimeConfig.ts` |
| 游戏首页主控制器 | `assets/Script/UI/Home/MainHomeView.ts` |
| 首页功能组合器 | `assets/Script/UI/Home/HomeFeatureComposer.ts` |

`MainHomeView.onLoad()` 里会做这些事：

1. `DisplayAdapter.apply()` 做屏幕适配。
2. `GameBackend.api.initialize()` 初始化后端数据。
3. `setupUILayers()` 建立 page/popup 层。
4. `mountHomeUIPrefabs(HOME_UI_STARTUP_PREFABS)` 预加载启动必需 popup。
5. `bindEntry(entry)` 绑定主界面按钮，点击时再加载对应页面 prefab。

### 2.2 Prefab 加载清单

所有首页 UI prefab 的加载清单在：

`assets/Script/UI/Home/HomeUIPrefabManifest.ts`

该文件负责两件事：

1. 告诉代码每个 rootName 对应哪个 prefab 路径。
2. 告诉代码点击哪个入口按钮时要加载哪些页面或弹窗。

如果新增一个页面或弹窗，必须在这里加。

## 9. 编辑器节点和代码同步规则

### 9.1 代码按名字找节点

很多代码会用类似方式找节点：

```ts
const node = this.findNode(root, 'SomeNodeName');
```

所以：

- 可以改位置、大小、颜色。
- 改节点名必须同步改代码。
- 删除节点前必须全文搜索节点名。

推荐搜索：

```powershell
rg -n "节点名" assets\Script assets\Bundle
```

### 9.2 运行时生成节点

这些通常在编辑器里看不到完整结构：

- 背包格子列表。
- 邮件列表行。
- 商铺商品列表。
- 集市商品列表。
- 魔界地图玩家/妖怪实例。
- 魔界打妖怪玩家站位、伤害统计行。
- 异兽强化装备位/宝石位部分交互状态。
- 礼包里的动态商品格子。

如果想让这些也能在编辑器里拖动，做法是：

1. 先在对应 prefab 里创建稳定节点。
2. 起一个明确名字。
3. 代码里先 `findNode` 读取这个节点。
4. 找不到时再创建 fallback。
5. 把运行时写死的位置改成读取编辑器节点的位置。

### 9.3 只换 UI 图，不改尺寸

很多弹窗和按钮尺寸已经按手机效果调过。只换 spriteFrame 时，不要顺手改 `UITransform` 尺寸。

典型例子：

- 通用确认弹窗 `ConfirmPopup`。
- 背包物品详情弹窗 `ItemDetailPopup`。
- 商铺购买弹窗。
- 魔界进入层数确认弹窗。

## 11. 新功能接入流程

### 11.1 新增 UI 页面

1. 在 `assets/Bundle/UIHome/Prefabs/Page` 或 `Popup` 创建 prefab。
2. 在 `HomeUIPrefabManifest.ts` 增加 rootName、layer、path。
3. 如果是入口点击加载，在 `HOME_UI_ENTRY_ROOT_NAMES` 加入口映射。
4. 新增 feature 文件，例如 `HomeFeatureXXX.ts`。
5. 在 `MainHomeView.ts` 里 import 并 compose。
6. 如果跨 feature 调用方法，在 `HomeViewBase.ts` 增加抽象方法声明。
7. 运行检查。

### 11.2 新增后端接口

1. 在 `GameBackendTypes.ts` 增加 DTO。
2. 在 `IGameBackend.ts` 增加方法。
3. 在 `RemoteGameBackend.ts` 实现 HTTP 请求。
4. 在 `LocalPreviewBackend.ts` 给本地预览实现。
5. 在对应 `HomeFeature*.ts` 里调用 `GameBackend.api.xxx()`。
6. UI 层只读接口返回的数据，不直接拼 HTTP。

### 11.3 新增资源

1. 放到正确 bundle 目录：
   - 魔界：`assets/Bundle/FeatureMagic`
   - 征战：`assets/Bundle/FeatureBattle`
   - 异兽：`assets/Bundle/FeatureBeast`
   - 背包：`assets/Bundle/FeatureBag`
   - 角色：`assets/Bundle/FeatureRole`
   - 公共：`assets/Bundle/Res`
2. 确认 `.meta` 存在。
3. 在配置里写资源路径，不要写系统绝对路径。
4. 如果资源前缀不在 `HomeAssetBundleManifest.ts` 里，要补规则。

## 12. 后端优先接入建议

为了不把前端本地预览状态和真实后端混在一起，建议按这个顺序接：

1. `initialize`：profile、inventory、serverTime、featureFlags。
2. 背包 inventory：装备必须实例化，一件装备一个 inventory item。
3. 邮件：托管奖励、系统奖励都由后端发邮件。
4. 商铺/礼包：购买扣元宝，后端返回新的 bootstrap 或局部库存。
5. 征战：挑战次数、托管状态、奖励结算。
6. 魔界：门票、每日次数、房间、50 人站位、怪物状态、保护卡/战力卡。
7. 异兽：兽卡激活、产出记录、强化状态。
8. 集市：上架、购买、撤回、成交记录。
9. 对决/乱世争雄：匹配、房间、回合、结算、排行。

## 14. 不要乱动的地方

这些位置不是不能改，而是改之前必须明确影响：

| 文件/目录 | 原因 |
| --- | --- |
| `assets/Script/UI/Home/HomeViewBase.ts` | 很多 feature 的抽象契约和共享状态都在这里 |
| `assets/Script/UI/Home/MainHomeView.ts` | 首页总入口，顺序错了会导致方法未挂载 |
| `assets/Script/UI/Home/HomeUIPrefabManifest.ts` | prefab 加载清单，少配会页面打不开 |
| `assets/Script/UI/Home/HomeAssetBundleManifest.ts` | bundle 分流，配错会资源加载失败 |
| `assets/Bundle/**.meta` | Cocos 资源 UUID 依赖 meta |
| `BagIllustrationCatalog.generated.ts` | 背包、图鉴、装备详情都依赖这里 |
| `HomeMagicConfig.ts` | 魔界大量位置和大小都在这里，容易互相影响 |
| `HomeBeastConfig.ts` | 异兽页面和强化页面共用配置多 |

4. 具体功能接 UI 的地方：
   - 征战：`HomeFeatureBattle*.ts`
   - 邮件：`HomeFeatureMail*.ts`
