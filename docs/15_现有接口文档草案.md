# 现有前后端接口文档草案

> 状态：草案，不是最终版。  
> 日期：2026-07-30。  
> 来源：当前前端工程 `assets/Script/Services/Backend/IGameBackend.ts`、`RemoteGameBackend.ts`、`GameBackendTypes.ts`、`BackendRuntime.ts`、`AuthService.ts`。  
> 目的：先让前端和后端同学对齐“现在前端已经预留了哪些接口、数据长什么样、后续还缺哪些接口”。

## 1. 当前接入状态

当前工程已经抽出了一层后端适配：

| 文件 | 作用 |
| --- | --- |
| `assets/Script/Services/Backend/IGameBackend.ts` | 前端认可的后端接口列表 |
| `assets/Script/Services/Backend/GameBackendTypes.ts` | 接口 DTO 类型定义 |
| `assets/Script/Services/Backend/RemoteGameBackend.ts` | 远程 HTTP 接口实现 |
| `assets/Script/Services/Backend/LocalPreviewBackend.ts` | 本地预览假数据实现 |
| `assets/Script/Services/BackendRuntime.ts` | 根据运行配置选择本地预览或远程后端 |
| `assets/Script/Services/AuthService.ts` | 当前本地登录逻辑，后续要替换为真实登录 |

默认运行模式是 `local-preview`，不会请求后端。只有运行时配置变成下面这种，前端才会调用远程服务：

```ts
globalThis.__QV_RUNTIME_CONFIG__ = {
    backendMode: 'remote',
    apiBaseUrl: 'http://localhost:8080',
    webSocketBaseUrl: 'ws://localhost:8080/ws',
    requestTimeoutMs: 10000,
    clientVersion: 'qv1.3-dev',
    resourceVersion: 'local',
    channel: 'dev',
};
```

## 2. 通用约定

### 2.1 基础路径

接口路径由 `apiBaseUrl + path` 组成。

示例：

```txt
apiBaseUrl = http://localhost:8080
path       = /v1/game/bootstrap
完整地址   = http://localhost:8080/v1/game/bootstrap
```

### 2.2 请求头

除登录接口外，远程接口会自动携带 token：

```http
Accept: application/json
Content-Type: application/json
Authorization: Bearer <token>
```

如果当前没有 token，前端不会传 `Authorization`。

### 2.3 返回格式

当前前端期望所有接口返回统一包裹结构：

```ts
interface ApiResult<T> {
    ok: boolean;
    data?: T;
    errorCode?: string;
    message?: string;
}
```

成功示例：

```json
{
  "ok": true,
  "data": {
    "serverTime": 1785393600000
  }
}
```

失败示例：

```json
{
  "ok": false,
  "errorCode": "INSUFFICIENT_CURRENCY",
  "message": "元宝不足"
}
```

前端当前会把非 `2xx` HTTP 状态识别为请求失败，建议后端业务失败也返回 JSON 格式的 `ApiResult`，方便前端展示中文提示。

### 2.4 时间与数字

| 字段 | 约定 |
| --- | --- |
| `serverTime` | 服务器当前时间，毫秒时间戳 |
| `createTime` | 邮件创建时间，毫秒时间戳 |
| `createdAt` | 集市挂单创建时间，毫秒时间戳 |
| `expiresAt` | 战斗会话过期时间，毫秒时间戳 |
| 金额、数量、等级、战力 | 统一使用整数 |

### 2.5 ID 约定

| 字段 | 含义 |
| --- | --- |
| `id` | 具体数据实例 ID，比如玩家 ID、邮件 ID、背包实例 ID |
| `templateId` | 配置表 ID，比如物品、道具、怪物、商品模板 |
| `playerId` | 玩家 ID |
| `battleId` | 服务端生成的战斗会话 ID |
| `listingId` | 集市挂单 ID |

`templateId` 后续应和数值表、前端资源配置统一，不建议前后端各自随便写字符串。

## 3. DTO 数据结构

### 3.1 PlayerProfileDto

玩家基础信息。

```ts
type Gender = 'male' | 'female';

interface PlayerProfileDto {
    id: string;
    name: string;
    gender: Gender;
    level: number;
    power: number;
    soul: number;
    points: number;
}
```

当前字段解释：

| 字段 | 说明 |
| --- | --- |
| `id` | 玩家唯一 ID |
| `name` | 玩家昵称 |
| `gender` | 性别，当前只有 `male` / `female` |
| `level` | 玩家等级 |
| `power` | 战力 |
| `soul` | 当前预留货币字段之一，后续需要确认是否对应元宝、灵石或其他资源 |
| `points` | 当前预留货币字段之一，后续需要确认是否对应积分、元宝或其他资源 |

注意：现在前端部分页面已经使用“元宝”“灵石”等中文概念，但接口字段还停留在 `soul`、`points` 两个临时名。正式联调前需要统一货币命名。

### 3.2 InventoryItemDto

背包物品实例。

```ts
interface InventoryItemDto {
    id: string;
    templateId: string;
    amount: number;
    locked?: boolean;
}
```

### 3.3 MailDto

邮件。

```ts
interface MailDto {
    id: string;
    category: 'normal' | 'system';
    title: string;
    content: string;
    senderName: string;
    createTime: number;
    state: 0 | 1 | 2;
    rewards: Array<{ templateId: string; amount: number }>;
}
```

邮件状态建议：

| `state` | 建议含义 |
| --- | --- |
| `0` | 未读 |
| `1` | 已读未领取 |
| `2` | 已领取或已处理 |

### 3.4 ShopProductDto

商店商品。

```ts
interface ShopProductDto {
    id: string;
    templateId: string;
    amount: number;
    price: number;
    currency: 'soul' | 'points';
    purchaseLimit?: number;
}
```

### 3.5 MarketListingDto

集市挂单。

```ts
interface MarketListingDto {
    id: string;
    sellerId: string;
    templateId: string;
    amount: number;
    unitPrice: number;
    createdAt: number;
}
```

### 3.6 RankingEntryDto

排行榜条目。

```ts
interface RankingEntryDto {
    rank: number;
    playerId: string;
    playerName: string;
    gender: Gender;
    value: number;
}
```

### 3.7 BattleStartDto

战斗开始数据。

```ts
interface BattleStartDto {
    battleId: string;
    seed: number;
    expiresAt: number;
    enemies: Array<{ id: string; templateId: string; hp: number }>;
}
```

### 3.8 BattleResultDto

战斗结算上报数据。

```ts
interface BattleResultDto {
    battleId: string;
    victory: boolean;
    damage: number;
    durationMs: number;
}
```

### 3.9 BootstrapDto

进入游戏时的初始数据快照。

```ts
interface BootstrapDto {
    profile: PlayerProfileDto;
    inventory: InventoryItemDto[];
    serverTime: number;
    featureFlags: Record<string, boolean>;
}
```

`BootstrapDto` 很重要，后续可以逐步扩展成“玩家登录后一次性拉取首页所需数据”的总入口。

### 5.1 拉取玩家初始数据

```http

```

返回：


示例：

```json

  "ok": true,
  "data": {
    "profile": {
      "id": "player_10001",

      "gender": "male",
      "level": 1,
      "power": 1200,
      "soul": 0,
      "points": 0

      "market": true,
      "battle": true
    }
  }

```

### 5.2 保存玩家资料

```http
PATCH /v1/player/profile
```

请求体：

```ts
Partial<PlayerProfileDto>
```

```json
{
```

```ts

```

后端注意：不要信任客户端提交的 `level`、`power`、`soul`、`points` 等核心数值。正式服建议只允许改昵称、头像、性别等展示字段，核心数值由服务端计算。

## 13. Spring Boot 后端实现建议

后端同学使用 Java、Spring Boot、Maven、JDBC、WebSocket 是可以的。建议按下面方式落地：

| 层 | 建议职责 |
| --- | --- |
| Controller | 只处理 HTTP 入参、鉴权上下文、返回 `ApiResult` |
| Service | 处理业务规则，比如购买、领奖、战斗结算 |
| Repository/DAO | 用 JDBC 读写数据库 |
| DTO | 和前端接口字段保持一致 |
| Config | 跨域、鉴权拦截、WebSocket 配置 |

建议包结构：

```txt
com.duxiachuan.server
├── common
│   ├── ApiResult.java
│   └── ErrorCode.java
├── auth
├── player
├── inventory
├── mail
├── shop
├── market
├── ranking
├── battle
└── websocket
```

建议优先完成顺序：

| 优先级 | 内容 | 原因 |
| --- | --- | --- |
| 1 | 登录、鉴权、玩家基础数据、`bootstrap` | 没有这个前端无法进入正式远程模式 |
| 2 | 背包、货币、邮件、商店 | 最容易形成完整闭环 |
| 3 | 战斗开始和战斗结算 | 游戏核心收益闭环 |
| 4 | 道友、分享任务、魔界卡 | 当前正在开发的功能 |
| 5 | 集市、排行、WebSocket | 多人在线体验和运营功能 |

## 15. 联调前必须确认的问题

1. `soul`、`points` 到底分别对应什么中文资源。现在前端 UI 里有“元宝”“灵石”等概念，必须统一。
2. 玩家 ID、物品配置 ID、怪物配置 ID、任务 ID 的命名规则。
3. `bootstrap` 是否一次性返回所有首页数据，还是只返回最小基础数据。
4. 战斗是客户端表现、服务端校验，还是服务端完整计算。
5. 分享任务和道友等级，是由后端实时统计，还是定时刷新。
6. 邮件奖励、分享奖励、战斗奖励是否都走统一奖励发放服务。
7. WebSocket 第一阶段是否先不接，只保留 HTTP。
8. 错误码是否由后端统一维护一份表，前端只负责展示 `message`。

## 16. 当前建议错误码

| errorCode | 建议含义 |
| --- | --- |
| `UNAUTHORIZED` | 未登录或 token 失效 |
| `FORBIDDEN` | 没有权限 |
| `INVALID_ARGUMENT` | 参数错误 |
| `NOT_FOUND` | 数据不存在 |
| `INSUFFICIENT_CURRENCY` | 货币不足 |
| `INSUFFICIENT_ITEM` | 道具不足 |
| `ALREADY_CLAIMED` | 已领取 |
| `BATTLE_EXPIRED` | 战斗会话过期 |
| `BATTLE_ALREADY_SUBMITTED` | 战斗已经结算 |
| `LOCAL_PREVIEW_ONLY` | 当前只支持本地预览 |
| `SERVER_ERROR` | 服务端未知错误 |

## 17. 当前草案结论

当前前端已经具备“可切换本地预览和远程后端”的雏形，但还不是完整上线协议。第一阶段后端不要一上来铺所有玩法，建议先把下面这个最小闭环打通：

```txt
登录
-> GET /v1/game/bootstrap
-> 邮件列表/领取
-> 商店列表/购买
-> 开始战斗
-> 提交战斗结果
```
