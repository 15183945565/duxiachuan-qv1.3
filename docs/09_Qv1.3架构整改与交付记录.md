优先级固定为 `feature-* > res > ui-home`，防止功能资源被复制回低优先级 Prefab Bundle。`HomeAssetBundleManifest.ts` 统一维护动态路径和入口到 Bundle 的映射：`TabShowcase` 路由到 `feature-magic`，`TabBattle` 路由到 `feature-battle`，`BtnDuel` 路由到 `feature-duel`，`TabBoss` 路由到 `feature-beast`，`BtnShop` 路由到 `feature-shop`，头像入口 `BtnProfile` 路由到 `feature-profile`，`TabBag` 路由到 `feature-bag`，`TabRole` 路由到 `feature-role`，`BtnShare` 路由到 `feature-share`，未命中功能前缀的资源才回落到共享 `res`。

`BottomFeaturePanel.prefab` 是魔界与兽卡共用的编辑器节点壳。实跑曾发现其中序列化了 75 处、36 个唯一的 Magic/Beast 资源引用，导致进入兽卡前 Cocos 强制要求先加载 `feature-magic`。现已清除这些功能资源引用，保留全部 230 个编辑器节点和输入层，页面打开后由统一路径路由回填 SpriteFrame/SkeletonData。`strip-shared-prefab-feature-references.mjs` 可重复执行清理，`check:bundles` 会阻止共享壳重新序列化任一功能 Bundle 资产。

商店拆分时发现 `MarketPanel`、物品详情和数量确认弹窗复用了四张交易通用纹理。它们现统一归入 `Texture/UI/Common/Commerce`，不再让市场或通用弹窗反向依赖 `feature-shop`；市场复用的分隔线也已按同一规则归入共享资源。Bundle 门禁会扫描全部功能资源 UUID，并验证启动 Prefab 不得引用功能包、每个按需 Prefab 的功能资源必须由对应入口显式获取。

背包资源按“玩法页面”和“物品基础设施”重新分界：171 张物品图、物品品质框和详情属性框被角色、商店、集市、战斗奖励、邮件、兽卡共同使用，继续留在共享 `res`；只有背包页面专用资源进入 `feature-bag`。图鉴详情 Prefab 已从启动组移到 `TabBag`。实跑还发现背包、邮件和战斗共同使用的操作按钮原被误放在 `feature-battle`，现已迁入 `Texture/UI/Common`，避免打开背包反向请求战斗包。

角色域同样按生命周期拆分：角色装备、升阶、强化页面 UI 进入 `feature-role`；主城常驻男女角色 Spine 继续保留在 `res`，因为它们是 MainScene 启动必需资产。角色、兽卡和共用底部壳复用的页面底图、装备选中框、替换弹窗背景归入 `Texture/UI/Common`。角色与征战共同使用的强化底板和奖励 Spine 也从 `feature-battle` 改归共享层，`TabRole` 不再为少量共用资产提前获取整个战斗包。

## 5. 资源生命周期

`ResourceManager` 已提供：

- Bundle 并发加载去重。
- `acquireBundle/releaseBundle` 引用计数。
- `ResourceScope` 按页面或玩法持有 Bundle 和动态 Asset。
- Asset `addRef/decRef` 成对管理。
- Bundle 和 Asset 诊断信息。
- Scope 销毁后释放资源并按条件移除 Bundle。

Home 内部原有的 8 处 `loadBundle('res')` 已全部收口到 `homeUiResourceScope`，角色、战斗、Toast、进阶条和主界面音乐不再新增永久固定。魔界、战斗、对决、兽卡、商店、档案、背包与角色页由 `homeFeatureResourceScopes` 按入口分别持有，并在 Home 销毁时与共享 Scope 分开释放。档案的三个 Prefab 已从启动组移入头像点击入口；已装备头像框只在确有本地保存状态时按动态路径获取对应功能包，未装备玩家不会为档案资源支付启动成本。Boot 与 PhoneLoginPanel 分别使用随组件销毁的独立 Scope；全局 SIMKAI 字体由应用生命周期 Scope 持有 Bundle 和字体 Asset。旧 `loadBundle`/`unpinBundle` 兼容接口与 `pinnedBundles` 状态已从 `ResourceManager` 物理删除。`check:bundles` 会扫描全部业务脚本，禁止重新引入永久固定调用，并强制检查 Bundle 优先级、路径路由、入口按需加载和构建体积。

## 9. Android 竖屏全屏适配修复

Android 真机曾出现 UI 仅占屏幕中央约 `58.6%`、四周大面积黑边。原因是两张场景的 Canvas 仍保留 `1280×720`，而 UI 与 Web Release 配置使用 `750×1624`；Android 构建没有读取 Web 专用配置，按 1280 逻辑宽度缩放了 750 宽 UI。

本轮已统一以下入口：

- `settings/v2/packages/project.json`：`750×1624`、`fitWidth=true`、`fitHeight=false`。
- `LoadingScene` 与 `MainScene`：Canvas 尺寸 `750×1624`、编辑器位置 `(375, 812)`、保持屏幕对齐。
- `DisplayAdapter`：运行时统一调用 `ResolutionPolicy.FIXED_WIDTH`。
- Loading 和 Main 生命周期：UI 初始化前应用，并在尺寸或方向变化时重算。
- `check:display`：阻止项目设置、场景 Canvas 和运行时策略再次漂移。

Android 原生方向仍由构建面板控制，必须保持竖屏。
