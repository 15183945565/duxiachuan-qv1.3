# 分享与道友开发说明

## 当前基线

分享任务和“我的道友”已从归档版迁入 `game/Qv1.3`。工程继续使用小型 `MainScene`、独立 UI Prefab、入口按需加载 Feature Bundle 的结构。

当前页面数据仍是 LocalPreview 演示数据。正式联调后，道友列表、任务进度、领取状态和元宝余额必须全部以服务端为唯一真值。

## 编辑器入口

分享页面：

`assets/Bundle/UIHome/Prefabs/Popup/SharePanel.prefab`

道友页面：

`assets/Bundle/UIHome/Prefabs/Popup/ProfilePopup.prefab`

道友节点路径：

`ProfilePopup/ProfileDaoYouPanel`

不要在 `MainScene` 中寻找这两个完整页面。`MainScene` 只保留常驻壳层，运行时根据入口加载并挂载 Prefab。

## 布局所有权

- Prefab/编辑器负责静态位置、宽高、字体、字号、颜色、皮肤和节点层级。
- TypeScript 负责文本数据、任务状态、进度条宽度、选中态、滚动内容高度和缺失节点兜底。
- 已存在的编辑器节点不得在运行时重新执行固定 `setPosition` 或固定 `setContentSize`。
- 只有新创建的兜底节点可以使用代码默认坐标和尺寸。
- 新增静态节点时先在 Prefab 中创建；脚本创建只作为资源缺失或旧存档兼容方案。

公共约束位于：

`assets/Script/UI/Home/HomeEditorLayout.ts`

`npm run check:code` 会检查分享和道友模块是否继续遵守编辑器布局所有权。

## 文件职责

- `HomeShareTaskPanel.ts`：分享任务绑定、状态刷新、跳转与领取演示。
- `HomeProfileDaoYouPanel.ts`：道友标签、列表数据填充和滚动行为。
- `HomeFeatureGiftShare.ts`：现有入口组合层，分享逻辑委托给 `HomeShareTaskPanel`。
- `HomeConfig.ts`：LocalPreview 任务和道友演示数据；正式接后端时不得继续作为线上真值。
- `HomeAssetBundleManifest.ts`：入口与资源 Bundle 路由。
- `SharePanel.prefab`、`ProfilePopup.prefab`：页面静态结构和可视化布局。

## Bundle 归属

- 分享贴图：`assets/Bundle/FeatureShare/Texture/UI/Share`
- 道友贴图：`assets/Bundle/FeatureProfile/Texture/UI/Profile/DaoYou`
- 页面 Prefab：`assets/Bundle/UIHome/Prefabs/Popup`

`BtnShare` 必须先获取 `feature-share`，再挂载 `SharePanel`。`BtnProfile` 必须先获取 `feature-profile`，再挂载 `ProfilePopup`。

不要把分享背景移回 `Res` 或直接塞进 `MainScene`。分享背景体积较大，独立 Bundle 可以避免增加首屏下载和常驻内存。

## 后端接口契约

建议按 OpenAPI 锁定以下接口。

### 道友列表

`GET /v1/social/allies?tier=chief|generation`

响应至少包含：

```ts
interface AllyDto {
    id: string;
    tier: 'chief' | 'generation';
    name: string;
    avatarUrl?: string;
    battleLevel: number;
    yuanbao: number;
}
```

服务端应返回稳定游标或分页信息，客户端不得假设列表永远只有当前演示数量。

### 分享任务

`GET /v1/social/share-tasks`

响应至少包含：

```ts
interface ShareTaskDto {
    id: string;
    tier: 'chief' | 'generation';
    requiredCount: number;
    requiredBattleLevel: number;
    progress: number;
    reward: { currency: 'yuanbao'; amount: number };
    status: 'in_progress' | 'claimable' | 'claimed';
}
```

任务进度和 `status` 必须由服务端计算，客户端只负责显示。

### 领取任务奖励

`POST /v1/social/share-tasks/{taskId}/claim`

请求必须带 `requestId` 或 `Idempotency-Key`。响应应包含任务最新状态、实际发放奖励和最新元宝余额。重复请求只能返回同一次发放结果，不能重复增加元宝。

建议错误码至少包含：

- `TASK_NOT_FOUND`
- `TASK_NOT_COMPLETE`
- `TASK_ALREADY_CLAIMED`
- `DUPLICATE_REQUEST`
- `UNAUTHORIZED`

## 后续接线顺序

1. 在 `GameBackendTypes.ts` 固化最终 DTO。
2. 在 `IGameBackend`、`LocalPreviewBackend`、`RemoteGameBackend` 同时增加能力。
3. 将 LocalPreview 数据从 `HomeConfig` 迁入 `LocalPreviewBackend`。
4. 页面通过 `GameBackend.api` 或统一 Store 读取数据，不直接 `fetch`。
5. 增加 Loading、Empty、Error、Retry、超时和重复点击保护。
6. 领取成功后统一刷新任务状态和货币 Store。
7. 删除 `claimedShareTaskIds` 等客户端线上真值。
