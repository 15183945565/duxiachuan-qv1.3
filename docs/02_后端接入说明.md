# 后端接入说明

## 接口入口

正式接口边界为：

```text
assets/Script/Services/Backend/
  GameBackendTypes.ts
  IGameBackend.ts
  GameBackend.ts
  LocalPreviewBackend.ts
  RemoteGameBackend.ts
```

页面只应依赖 `GameBackend.api`。当前默认使用 `LocalPreviewBackend`，用于无服务器演示。

## 当前联调状态

接口边界已经建立，但业务页面尚未完成端到端接线：

- `MainHomeView` 当前只调用一次 `GameBackend.api.initialize()`，返回的 Bootstrap 尚未回填 UI。
- 邮件、商城、集市、排行、战斗等 Remote 方法已有参考实现，但页面仍主要操作本地演示状态。
- 手机验证码、登录、token 签发仍是 `AuthService` 的本地预览逻辑。
- 因此当前适合锁定协议和并行开发 Mock Server，不适合宣称“改一个 baseUrl 就完成联调”。

## HTTP 传输边界

`RemoteGameBackend` 已完成可复用的 HTTP 基础边界：

- `baseUrl` 必须是绝对 HTTP(S) 地址，路径参数统一编码。
- 仅在存在 token 时发送 `Authorization`，仅在存在请求体时发送 `Content-Type: application/json`。
- 请求统一带超时和取消信号，并区分 `TIMEOUT`、`NETWORK_ERROR`、`INVALID_RESPONSE` 与服务端业务错误。
- JSON 响应先按文本读取再解析；空的 `204` 响应按 `{ "ok": true }` 处理。
- 非 2xx 响应优先使用服务端 `errorCode/message`，缺失时回退到 HTTP 状态码。

`npm run check:backend` 会禁止业务代码绕过该边界直接使用 `fetch`，并锁定已审查的 8 个 localStorage 真值所有者。该传输层已经可用于 Mock Server 和真实接口开发，但它不替代 OpenAPI 锁定、DTO 映射、Bootstrap 回填和页面事务接线。

## 切换正式服务器的唯一入口

在登录成功并取得 token 后配置一次：

```ts
import { AuthService } from './assets/Script/Services/AuthService';
import { GameBackend } from './assets/Script/Services/Backend/GameBackend';
import { RemoteGameBackend } from './assets/Script/Services/Backend/RemoteGameBackend';

GameBackend.configure(new RemoteGameBackend({
    baseUrl: 'https://api.example.com',
    tokenProvider: () => AuthService.getToken(),
    timeoutMs: 10000,
}));
```

实际项目中应放到登录成功后的会话初始化服务，不要散落在页面代码中。

## 运行时环境注入

Web Mobile 构建通过标准 Cocos 项目模板 `build-templates/web-mobile/`，在应用脚本启动前加载固定文件名 `runtime-config.js`。源代码模板只提供 `local-preview` 默认值，不包含任何真实服务器地址、token 或生产密钥。

部署系统应在发布包中替换 `runtime-config.js`，而不是修改已带 MD5 的业务脚本：

```js
globalThis.__QV_RUNTIME_CONFIG__ = Object.freeze({
    backendMode: 'remote',
    apiBaseUrl: 'https://api.example.com',
    webSocketBaseUrl: 'wss://ws.example.com',
    cdnBaseUrl: 'https://cdn.example.com/game',
    requestTimeoutMs: 10000,
    clientVersion: '1.4.0',
    resourceVersion: '20260727.1',
    channel: 'web',
});
```

允许字段仅为后端模式、API/WS/CDN 地址、超时、客户端版本、资源版本和渠道。未知字段、疑似 token/secret/password/private key 字段、URL 内嵌账号密码、非法协议和超范围超时会在 LoadingScene 初始化时直接拒绝。Release 的 MD5 配置明确排除 `runtime-config.js`，因此各环境可以复用同一份构建产物。

当前手机号登录仍是本地预览逻辑；在真实登录、token 刷新和退出协议接通前，不应把生产部署配置切到 `remote`。

## 已定义接口

- `initialize`：角色、货币、背包和功能开关快照。
- `saveProfile`：角色名、性别等资料。
- `list/read/claim/deleteMail`：邮件完整流程。
- `listShopProducts/purchaseProduct`：商店。
- `listMarket/buy/createMarketListing`：集市。
- `listRankings`：战力和战场等级排行。
- `startBattle/submitBattleResult`：征战、魔界等战斗。

`RemoteGameBackend` 当前参考路径：

| 能力 | 方法与路径 |
|---|---|
| 启动快照 | `GET /v1/game/bootstrap` |
| 保存资料 | `PATCH /v1/player/profile` |
| 邮件 | `GET/POST/DELETE /v1/mails...` |
| 商城 | `GET /v1/shop/products`、`POST /v1/shop/purchase` |
| 集市 | `GET/POST /v1/market/listings...` |
| 排行 | `GET /v1/rankings/{type}` |
| 战斗 | `POST /v1/battles/start`、`POST /v1/battles/{id}/result` |

这些路径是当前前端契约，不代表后端必须无条件接受。联调开始前双方应锁定一次 OpenAPI，并同步修改接口、DTO、错误码和幂等规则。

## 服务端必须负责

- 登录验证码校验、token 签发与刷新。
- 货币、背包、装备、升级、强化和合成事务。
- 邮件奖励幂等领取。
- 商城购买限购与扣款。
- 集市并发购买、撤单和交易记录。
- 战斗种子、敌人快照、超时和结算校验。
- 排行榜和对决状态。

宗门、礼包、分享当前冻结，不进入首版接口范围。

## 建议响应格式

```json
{
  "ok": true,
  "data": {},
  "errorCode": "",
  "message": ""
}
```

失败时 `ok=false`，客户端只显示 `message`，逻辑分支使用稳定的 `errorCode`。

## 本地存储迁移

当前 localStorage 分布在：

- `AuthService.ts`：本地 token、手机号和本地用户映射。
- `HomeFeatureMailData.ts`：邮件。
- `HomeFeatureShop.ts`：商城购买状态。
- `HomeFeatureBeastStrengthenRules.ts`：兽卡强化。
- `HomeFeatureProfileShell/AvatarFrame/Settings.ts`：档案、头像框和音频偏好。
- `HomeFeatureNotice.ts`：公告当日已打开标记。

后端接入必须按“一个字段只有一个真值来源”迁移。服务端接管的字段先完成 DTO 映射、Loading/Error/Retry 和回滚，再删除对应本地读写；音量、画质等纯设备偏好可以继续保留本地。

## 联调前必须确认

1. 验证码发送、登录/注册、token 刷新和退出协议。
2. `BootstrapDto` 是否一次返回角色、货币、背包、装备、功能开关和服务端时间。
3. 物品模板 ID 与物品实例 ID 的区分规则。
4. 邮件领取、商城购买、集市交易和战斗结算的幂等键。
5. HTTP 状态码、业务 `errorCode`、维护状态和强制更新状态。
6. 客户端版本、资源版本、渠道、时区和请求追踪字段。
7. API、WebSocket 和 CDN 的开发/测试/预发布/生产地址注入方式。
