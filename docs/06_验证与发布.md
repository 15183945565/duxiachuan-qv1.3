# 验证与发布

## 自动检查

```powershell
npm run check:all
```

该命令依次检查：

1. 场景 UUID 能否在 `.meta` 中解析。
2. 固定编辑器节点的完整父子路径。
3. 项目默认分辨率、两张场景 Canvas 和运行时 `FIXED_WIDTH` 入口是否一致。
4. TypeScript 相对导入、脚本 Meta 和 `HomeConfig` 引用完整性。
5. 资源与 `.meta` 配对、动态资源路径和 Spine 包完整性。
6. Bundle 路由、启动/按需依赖和构建体积预算。
7. Web Mobile 启动场景、引擎版本、远程资源配置完整性和单文件上限。
8. 交付目录是否混入缓存、构建、日志、预览图或临时文件。

Creator 首次打开会生成 `temp/tsconfig.cocos.json`。随后使用 Creator 内置 TypeScript 编译器确认脚本为零错误。

## 人工必测

1. LoadingScene 加载、修复和登录可操作。
2. 新账号可创建角色并进入 MainScene。
3. 所有左右入口和底部入口都能打开并返回。
4. 角色升级、突破、强化和装备替换可完成。
5. 背包图鉴、分解确认和合成页可操作。
6. 邮件托管奖励可查看、领取并弹出恭喜获得。
7. 征战普通/定向挑战、托管和战场升级可进入。
8. 魔界地图、怪物战斗和兽卡切换可进入并退出。
9. Creator 控制台无 Missing Script、Missing Asset 和持续报错。

## 构建与环境

构建输出统一进入 `build/`，不回传源码目录。发布环境应注入 API、WebSocket、CDN、版本号、渠道和资源版本，禁止把生产密钥写进前端仓库。

Android 构建必须选择竖屏，并在真机至少覆盖一台 `20:9` 或更长比例设备。项目源配置固定为 `750×1624 + Fit Width`；不要依赖 Web Mobile 构建配置替 Android 设置分辨率。若安装包仍显示旧画面，先卸载旧包再安装新 APK，排除壳层或热更新缓存。

正式 Web Mobile 构建使用：

```powershell
& 'C:\ProgramData\cocos\editors\Creator\3.8.8\CocosCreator.exe' `
  --project 'C:\Users\34158\Desktop\game\Qv1.3' `
  --build 'configPath=C:\Users\34158\Desktop\game\Qv1.3\tools\build-config\web-mobile.release.json'

npm run check:delivery:release
```

Release 配置固定 `debug=false`、`md5Cache=true`、`LoadingScene`、`750×1624`、`FIXED_WIDTH` 和竖屏。CDN 地址未确定前，不得只勾选远程 Bundle；资源服务器地址和远程包必须同时落地。

启动请求复验：

```powershell
npm run preview:web:release -- --log-requests
# 完成 LoadingScene → 登录 → MainScene 后停止预览
npm run check:delivery:startup
```

当前基线为 210 个唯一请求、43.57 MiB 原始响应、0 个功能 Bundle 请求；预算为 50 MiB。生产服务器应对 JS/JSON/TTF 启用 Brotli 或 gzip，并对带 MD5 的静态资源设置长期不可变缓存。

## 基线

`Qv1.2` 保留为整理前源版本，`Qv1.3` 是纯净迁移基线，`Qv1.3` 是当前架构整改和后端联调准备基线。后端接手后应立即建立版本库并提交一次只包含当前纯净源码的基线提交。
