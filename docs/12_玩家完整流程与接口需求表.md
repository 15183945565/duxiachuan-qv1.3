# Qv1.3 玩家完整流程清单、页面模块表与接口需求表

目标：从现有 Qv1.3 出发，把玩家进入游戏后的完整前端流程走通，并给后续页面开发、后端联调和验收提供统一清单。

## 1. 当前结论

Qv1.3 已经具备继续开发的正式工程骨架：

- `LoadingScene` 已有启动加载、修复入口、手机登录面板、健康提示、协议提示、进入游戏按钮。
- `MainScene` 已收敛为主界面壳层，功能页通过 `ui-home` Prefab 按需挂载。
- Home 已注册 11 个 Page、20 个 Popup，入口和资源 Bundle 已经通过 manifest 管理。
- 后端边界已有 `GameBackend.api`、`IGameBackend`、`LocalPreviewBackend`、`RemoteGameBackend`。
- 远端 HTTP 方法已经覆盖 Bootstrap、邮件、商店、集市、排行榜、战斗开始与战斗结算。

但 Qv1.3 还不是“接上服务器即可全流程联调”的状态：

- 手机登录仍在 `AuthService` 使用本地预览逻辑和 localStorage token。
- `GameBackend.api.initialize()` 目前只在主界面启动时调用，Bootstrap 数据尚未原子回填到统一 Session/Store。
- 邮件、商店、集市、角色、兽卡等多个页面还保留本地演示状态或 localStorage 真值。
- 角色创建、角色选择、背包、装备、养成、公告、对决等接口还需要补齐或细化。

下一阶段应先做一条“可玩竖切链路”，再扩展其它系统：

```text
启动 -> 手机登录 -> 进入游戏 -> Bootstrap -> 创建/选择角色 -> 主界面
-> 进入一个核心玩法 -> 战斗/挑战 -> 结算奖励 -> 背包/角色刷新 -> 回主界面
```

## 5. 接口需求表

### 5.1 通用约定

| 项目 | 建议约定 |
|---|---|
| 返回格式 | 继续使用 `ApiResult<T>`：`{ ok, data?, errorCode?, message? }` |
| 鉴权 | 登录后所有业务接口走 `Authorization: Bearer <token>` |
| 幂等 | 购买、领取、上架、结算、养成等事务接口必须支持 `requestId` 或 `idempotencyKey` |
| 时间 | 倒计时、邮件时间、对决回合、战斗过期全部以服务端 `serverTime` 为准 |
| 错误码 | 至少区分 `UNAUTHORIZED`、`TOKEN_EXPIRED`、`NETWORK_ERROR`、`TIMEOUT`、`NOT_ENOUGH_CURRENCY`、`ITEM_NOT_FOUND`、`DUPLICATE_REQUEST`、`BATTLE_EXPIRED` |
| 客户端状态 | 服务端字段不能长期同时由 localStorage 维护；localStorage 只保留本地设置、最后手机号、临时预览状态 |
| 事务返回 | 会影响多系统的接口优先返回 `BootstrapDto` 或统一 `GameStatePatchDto` |

| 能力 | 当前前端 | 建议接口 | 请求要点 | 响应要点 | 状态 |

## 6. 建议开发顺序

### P0：联调前基础

1. 锁定 OpenAPI、错误码、鉴权、幂等、环境配置。
2. 给 `AuthService` 增加真实短信登录能力，保留 LocalPreview 分支。
3. 建立 `Session/Store`：统一保存 profile、inventory、currencies、featureFlags、redDots、serverTime。
4. `MainHomeView` 启动时等待 Bootstrap 并回填 UI。
5. 把服务端字段从 localStorage 真值迁出，只保留本地设置类数据。

### P1：第一条可玩竖切

1. 创建/选择角色接服务端。
2. 主界面 HUD 读取 Store。
3. 征战 `startBattle` 接入。
4. 战斗结果 `submitBattleResult` 接入。
5. 奖励弹窗和背包/货币刷新接 BootstrapDto 或 Patch。
6. 从 `LoadingScene` 实跑完整链路并记录验收问题。

### P2：主界面常用系统

1. 邮件。
2. 商店。
3. 背包分解/合成/使用。
4. 角色装备与养成。
5. 公告和排行榜。

### P3：较复杂玩法

1. 魔界地图与魔界战斗。
2. 对决。
3. 集市并发交易。
4. 兽卡收益。
5. 宗门、礼包视产品排期再解冻；分享任务按 `13_分享与道友开发说明.md` 接口契约继续开发。

## 7. 每轮开发完成定义

一个页面或接口只有同时满足这些条件，才算真正走通：

- 页面静态结构在正确 Scene/Prefab 中，编辑器保存后启动效果一致。
- 页面只通过 `GameBackend.api` 或 Store 读取线上数据，不直接 `fetch`。
- 事务按钮有 pending、防重复点击、失败恢复。
- 有 Loading、Empty、Error、Retry、超时和取消后的有效性判断。
- 服务端返回后统一刷新 Store，不在多个页面各自维护同一份真值。
- localStorage 中不再保存该线上字段的第二份真值。
- 相关 Bundle 和 ResourceScope 生命周期正确。
- 从 `LoadingScene` 的真实入口完整实跑通过。
- 至少执行相关检查：`npm run check:ui`、`npm run check:backend`、`npm run check:code`、`npm run check:type`。
